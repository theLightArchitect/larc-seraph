SERAPH-YARA-003 · yara · high

MCP config decodes a payload into a shell or eval

An MCP client config pipes a base64 decode into a shell, or pairs a base64 decode call with eval or exec.

AuthorKevin Francis Tan · Light Architects
Date2026-11-13
ATT&CKT1027, T1140, T1059.004
Tacticdefense-evasion, execution
LicenseDetection Rule License 1.1
ScopeMCP client configs that contain an mcpServers object. A long token alone is not enough.

False positives

  • A server whose documented command line legitimately shells out through a decode step. Rare in MCP configs. The rule does not flag a bare base64 blob.

References

  • https://attack.mitre.org/techniques/T1027/
  • https://attack.mitre.org/techniques/T1140/
  • https://attack.mitre.org/techniques/T1059/004/

Threat

Encoding is a way to keep a command out of a casual read of a JSON file. The interesting event is not the presence of a long token. Tokens are normal. The interesting event is a decode step whose output is handed to a shell, or a decode call placed inside eval or exec.

Why this rule

The rule requires the MCP server map and one of those two shapes. A long opaque string in an environment value, with no decode flag and no eval, is a negative fixture on purpose. The synthetic decode used in the fixtures is the ASCII sentence echo seraph-inert, so a reviewer can reverse it and see that the sample is inert.

Limitations

A custom decoder, or a decode that writes a file instead of executing, does not match. A legitimate tool whose command line really does decode-and-exec will match and needs a human. The rule will not flag a blob that is never decoded in the file.

Triage

Decode the blob in a scratch buffer. The pack's own fixtures decode to an echo sentence. If the decoded text is a command the operator did not ask for, remove the entry.

Fixtures live under tests/fixtures/yara/SERAPH_MCP_Encoded_Exec/. Positives match this rule and no other larc-seraph rule. Negatives match none.
